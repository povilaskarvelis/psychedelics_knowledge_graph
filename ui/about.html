Methods

This page focuses on the decisions that shape the evidence base: search seeds, abstract screening, full-text access, extraction, validation, and provenance.

Scope

The graph connects psychedelic compounds with clinical indications and mechanistic targets. Each edge is backed by paper-level claims with source metadata, access level, evidence type, and a locator when available.

Default graph view

The interface defaults to primary evidence. Reviews, systematic reviews, and meta-analyses are retained as secondary literature and can be included explicitly.

Literature Search

Seed Strategy

Search starts from curated seed lists, not a single generic query. Seeds combine psychedelic compound names and aliases with clinical indications, mechanistic targets, and study-design terms. This is one of the most important parts of the pipeline: missing aliases or missing compound-target and compound-indication pairs become blind spots in the graph.

Searches run across OpenAlex, Semantic Scholar, PubMed/PMC, Crossref, and open-access metadata sources. A known relevant study set is used as a search-completeness check, so missed expected studies can trigger better synonyms, additional seeds, citation chasing, or a documented scope decision.

Search inputs

  • Compound names, aliases, and drug-class terms
  • Clinical indication and mechanistic target vocabularies
  • Provider-specific query variants
  • Known relevant studies for recall checks

Screening

Abstract Screening

Deterministic Pre-Screen

The first gate removes only obvious no-signal records: papers with enough abstract text but no in-scope compound, intervention, target, indication, or candidate context. Ambiguous records are kept.

LLM Screening

Retained abstracts are reviewed by a local LLM for relevance and quote-supported contexts. Screening happens at the DOI-compound-entity level, so one paper can support multiple graph edges without being collapsed into a single yes/no paper decision.

Abstract screening produces relevant, uncertain, and full-text candidate queues. It does not extract final claims or assign source family; those are later evidence-assessment tasks.

Extraction

Full Text And Data Extraction

Records that pass screening, plus uncertain records that need more context, are used for legal open-access PDF retrieval. Full text is converted into reusable artifacts and then used for LLM-assisted evidence assessment and data extraction.

Extraction captures the information needed for the graph: source family, paper type, study design, access level, evidence location, evidence locator, disorder outcome direction, clinical outcome details, and mechanistic assay values where available. If full text is not available, an abstract-only fallback can be used and is labeled as such.

Published text boundary

The public graph stores identifiers, structured claims, metadata, and provenance. Closed-access PDFs or long full-text passages are not redistributed.

Validation

Curation And Publication

Extracted rows are promoted only after schema and evidence-policy checks. The default graph view includes primary evidence. Reviews, systematic reviews, and meta-analyses are retained separately as secondary literature rather than counted as primary evidence.

Every published claim should keep enough provenance to audit it: paper/source type, access level, study design, evidence location, evidence locator, and result direction for disorder claims. These labels are descriptive. They are not a formal GRADE or Cochrane certainty assessment.

Limits

Current Limits

Coverage depends on the seed vocabulary, source indexing, DOI metadata, and access to full text. LLM outputs are useful for scaling screening and extraction, but they remain auditable proposals rather than unreviewable ground truth.

Living Evidence

Update Model

New literature searches can be run on a schedule, queued records can be screened, and validated graph payloads can be regenerated when accepted evidence changes. The first public release prioritizes auditable provenance over automatic publication.

Planned update pattern

Weekly discovery with a rolling lookback is the likely default. LLM screening and extraction can remain batch-reviewed until the calibration data are strong enough for more automation.

Reuse And Access

Data Boundaries

The public graph is intended to expose identifiers, metadata, structured factual claims, provenance fields, and project-authored summaries. It should not publish closed-access PDFs, closed-access full text, or long copyrighted passages. Open-access source material should still be handled according to the license attached to each article or provider record.

Community Feedback

Feedback

Corrections are part of the method. Missing papers, wrong edges, extraction errors, ambiguous evidence labels, and scope suggestions are all useful signals for improving the pipeline.
