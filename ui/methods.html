Methods

How the Psychedelics Knowledge Graph is assembled: what literature is searched, how papers are screened, how evidence is extracted, and how graph edges stay traceable.

Overview

What This Graph Is

This project is a living literature map for psychedelic compounds. It turns paper metadata and extracted evidence into a provenance-aware knowledge graph that can be inspected, rebuilt, and corrected as the literature changes.

The public interface shows the current graph build: one generated version of the evidence graph, not a final review article. It summarizes two evidence lanes, keeps the search and screening record visible, and links graph edges back to the papers and evidence records that support them.

The sections below follow that path in order: scope, seed words, screening and extraction, paper flow, graph outputs, and limits.

01

Searchable Evidence

Literature discovery starts from selected compound-indication and compound-target seed pairs rather than every possible vocabulary combination.

02

Traceable Decisions

Search results, screening decisions, retrieval status, extraction status, and exclusions are kept as auditable records.

03

Structured Graph Data

Papers, claims, entities, provenance, and evidence-quality fields are stored as structured objects for the interface and other tools.

04

Updateable Workflow

Discovery, screening, extraction, validation, and graph generation can be rerun when new studies or corrections appear.

Scope

What the Evidence Base Covers

The project follows two evidence lanes. One tracks clinical relationships between psychedelic compounds and indications. The other tracks mechanistic relationships between compounds and targets. Both lanes have explicit vocabularies and search seeds, so the scope of the graph can be inspected and improved. In the current graph build, the discovery search used selected starter pairs from those vocabularies; it was not an exhaustive search over every compound, indication, and target combination.

Clinical Indications

Human outcome evidence for disorders, symptoms, and clinical indications, with result direction recorded when claims are extracted.

Mechanistic Targets

Receptor, transporter, assay, and mechanistic evidence that links compounds to biological targets.

Source Types

Primary studies drive the default graph. Reviews, protocols, conference abstracts, commentary, and corrections are kept as separate context.

At A Glance

How the Current Graph Build Was Made

Here, graph build means the public graph generated from the current source files. The exact seed queries, search reports, screening decisions, claim files, validation reports, and build manifest are kept with the source data so the path from literature search to visible graph edge can be audited.

Search Sources

Discovery uses OpenAlex, Semantic Scholar, PubMed/PMC, Crossref, and open-access metadata sources. Starter seeds, generated provider-specific query variants, and provider counts are recorded in the discovery reports and ledgers.

Screening Role

Abstract screening decides whether a paper-context is relevant enough to pursue. It does not assign study design, evidence strength, or final graph inclusion.

Evidence Role

Full-text or clearly labeled abstract-only assessment supplies the source type, study variables, result direction, evidence locator, and reviewable claim proposal.

Search Seeds

Search Vocabulary Used For Discovery

The search vocabulary has several layers, but only some layers were used in the current checked-in discovery run. That run starts from 24 default mechanistic seed pairs and 41 default clinical seed pairs, then generates provider-specific variants with aliases, fielded database syntax, and evidence terms. Those expanded report rows contain 46 distinct mechanistic query strings and 119 distinct clinical query strings.

The default starter list is not the whole planned vocabulary. The canonical validation and expansion vocabulary is broader: 40 compounds, 46 mechanistic targets, and 31 clinical indications. Broader generated-seed and balanced-coverage modes can use those allowlists, but those modes were not enabled for the current checked-in reports. The exact settings for a run are stored with each discovery report, and the long provider-expanded query strings are stored in the reports rather than repeated in full here.

Starter Seed Pairs

Human-written compound-entity search phrases used as the default run inputs: 24 mechanistic and 41 clinical.

Provider Variants

Database-specific query strings add aliases, title/abstract fields, clinical-trial terms, and assay terms.

Canonical Vocabulary

The broader allowlists define what compounds, targets, and indications can be validated or used for expanded runs.

How the current search used those terms

The current checked-in search did not submit every candidate compound name by itself, and it did not search every possible compound-by-indication or compound-by-target combination. It searched the default compound-entity seed pairs listed below. For each pair, provider-specific variants added aliases and evidence terms, for example compound aliases AND indication aliases AND trial terms for clinical searches, or compound aliases AND target aliases AND binding/assay terms for mechanistic searches.

The broader allowlists are therefore the validation and expansion vocabulary, not proof that every possible pair was searched in this graph build. In practical terms, coverage is broad around the selected starter pairs and across multiple literature providers, but it is not broad across the full canonical vocabulary. The pipeline has modes for broader generated-seed and balanced-coverage searches, but those modes were off in the current discovery reports.

Pipeline

From Search to Evidence Records

The pipeline is designed to keep every major decision visible: what was searched, what was screened out, what could be retrieved, what could be converted, and what was finally extracted as graph evidence.

A record is a candidate bibliographic item; a paper is the deduplicated work in the library; a paper-context is a paper paired with a compound and indication or target; and a claim is the structured evidence record that can support a graph edge.

01

Literature Discovery

Searches start from selected compound-entity seed pairs, not from every vocabulary term alone. The current graph build used the default starter pairs; each pair was expanded into provider-specific query variants using aliases and evidence terms. Records are gathered from OpenAlex, Semantic Scholar, PubMed/PMC, Crossref, and open-access metadata sources.

Deduplication happens as records enter the paper library: a candidate is added only when DOI and title matching indicate that it is not already present. Known relevant studies are used as recall checks, so missed expected papers can lead to better seeds or a documented scope decision.

02

Screening and Eligibility

Abstract screening is the first relevance gate. A conservative pre-screen removes obvious no-signal records, then LLM-assisted screening reviews abstracts at the paper-context level, such as a DOI paired with a compound and indication or target.

At this stage the model is used only for relevance and quote-supported context checks. Source type, study design, evidence strength, extracted outcomes, and graph inclusion are handled later through evidence assessment, curation, and validation.

Uncertain records are retained for later assessment. Full-text eligibility is a separate step after retrieval, because some papers that look relevant from the abstract can become out of scope once the full report is inspected.

03

Retrieval and Conversion

Records that pass screening are queued for legal open-access full-text retrieval. The pipeline tracks whether a PDF was downloaded, unavailable, inaccessible, invalid, or converted into reusable text.

Papers with no retrievable full text can remain in an abstract-only path. That path is labeled explicitly, so later claims do not look as if full text was inspected.

04

Evidence Extraction

Extraction captures the fields needed for the graph: source type, study design, access level, evidence location, result direction, outcome details, assay values, funding, conflicts of interest, and risk-of-bias notes where available.

LLM outputs are treated as reviewable proposals tied to source records and locators. Accepted evidence is promoted only after schema and evidence-policy checks. Risk-of-bias notes are descriptive fields extracted from the source when available, not formal GRADE or Cochrane risk-of-bias ratings.

Knowledge Graph

How the Evidence Becomes a Graph

The graph connects psychedelic compounds to clinical indications and mechanistic targets. Each visible edge is meant to point back to papers, evidence records, access status, study context, and text locations when available.

The public view is deliberately selective. It shows the relationships that are easiest to read, while the underlying files keep the paper and claim details needed for checks and future updates.

Paper Layer

Paper records store discovery metadata, bibliographic details, screening decisions, retrieval status, and conversion status.

Claim Layer

Claim records store extracted evidence, result direction, study design, access level, and the source location that supports the claim.

Canonical Entity Layer

Compounds, indications, targets, papers, and evidence records are normalized into stable graph objects where possible.

Semantic Edge Layer

Evidence is aggregated into relationships such as compound to indication and compound to target.

View Layer

View files turn the underlying graph into readable interfaces: the main graph, literature landscape, paper flow, and gap view.

Quality Controls

Limits, Updates, And Reuse

Coverage depends on the seed vocabulary, source indexing, DOI metadata, and access to full text. LLMs help scale screening and extraction, but their outputs stay tied to reviewable records. Evidence labels and risk-of-bias notes are descriptive unless a formal certainty or risk-of-bias workflow is added.

Validation

Curated rows are checked against schemas and evidence-policy rules before they are promoted into public graph files.

Known Limits

Search terms, provider indexing, missing abstracts, access restrictions, and PDF conversion quality all shape coverage.

Living Evidence

New searches can be scheduled, queued records can be screened, and graph files can be rebuilt when accepted evidence changes.

Data Boundary

The public graph publishes identifiers, metadata, structured claims, provenance, and project-written summaries. Source texts remain governed by article licenses and copyright.
